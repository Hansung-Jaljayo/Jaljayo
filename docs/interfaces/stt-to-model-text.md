# STT 글자를 모델 입력으로 바꾸는 규칙

STT(말을 글자로 바꾸는 프로그램)가 숫자를 "30"처럼 숫자로 적을 수 있습니다. 학습 문장은 숫자를 모두 한글로 쓰기 때문에, 보드 앱은 STT 결과를 모델에 넣기 전에 이 규칙대로 한글로 바꿉니다.

- 처리 순서: 마이크 → STT 결과(원문) → **이 규칙으로 변환** → 모델 입력
- 원문과 변환문을 둘 다 기록합니다. 틀렸을 때 STT 문제인지 변환 문제인지 나눠 보기 위해서입니다.
- 학습 문장, 평가 문장, 보드 입력에 모두 같은 규칙을 씁니다.
- **글자 모양만 바꿉니다.** 오전·오후나 명령의 뜻을 추측해서 덧붙이지 않습니다. "11시"를 "오전 열한 시"로 바꾸지 않습니다.
- 멈춤 단어 검사("멈춰", "야 타임" 등)는 이 변환보다 먼저 원문으로 합니다.
- 관련 문서: [상세 설계서](../system-design.md) 8절 "모델에 무엇을 넣고 앱이 무엇을 채우나", 규격 `ai/spec/spec.py` 맨 위 출력 규칙

## 읽는 법

1시부터 12시까지의 시와 기간을 뜻하는 "시간"은 고유어(한, 두, 세)로 읽고, 그 밖의 숫자는 한자어(일, 이, 삼)로 읽습니다. STT가 이미 한글로 적었으면("열여덟 시") 바꾸지 않습니다.

| 단위 | 읽는 법 | 예 |
|---|---|---|
| 시 (1에서 12) | 고유어 | 1시 → 한 시, 11시 → 열한 시, 12시 → 열두 시 |
| 시 (13에서 24) | 한자어 | 18시 → 십팔 시, 23시 → 이십삼 시, 24시 → 이십사 시 |
| 시간(기간) | 고유어 | 1시간 → 한 시간, 2시간 → 두 시간, 12시간 → 열두 시간, 24시간 → 스물네 시간 |
| 분 | 한자어 | 5분 → 오 분, 11분 → 십일 분, 30분 → 삼십 분 |
| 도(각도) | 한자어 | 11도 → 십일 도, 0도 → 영 도 |
| 일(날짜, 기간) | 한자어 | 29일 → 이십구 일, 5일간 → 오 일간 |
| 월 | 한자어, 6월과 10월은 유월과 시월 | 10월 → 시월, 6월 → 유월, 3월 → 삼월 |
| 그 밖의 숫자(숫자 대답 등) | 한자어 | 11 → 십일, 198 → 백구십팔, 0 → 영 |

## 예

| STT 결과 | 모델에 넣을 문장 |
|---|---|
| 11시 | 열한 시 |
| 11분 | 십일 분 |
| 11도 | 십일 도 |
| 오후 11:05 | 오후 열한 시 오 분 |
| 11:30에 깨워줘 | 열한 시 삼십 분에 깨워줘 |
| 18시에 알람 | 십팔 시에 알람 |
| 1시간 뒤에 깨워 | 한 시간 뒤에 깨워 |
| 24시에 깨워 | 이십사 시에 깨워 |
| 30분 뒤에 깨워 | 삼십 분 뒤에 깨워 |
| 10월 15일 | 시월 십오 일 |
| (숫자 대답) 11 | 십일 |

## 24시

"24시"는 "그날이 끝나는 자정"입니다. 모델은 들은 그대로 `time=24:00`을 내고, 앱이 날짜를 넘깁니다. 24:30처럼 24시 뒤의 분은 받지 않습니다. "24시간 뒤"는 시각이 아니라 기간입니다.

| 말 | 앱이 정하는 때 |
|---|---|
| 오늘 24시 | 내일 0시 |
| 내일 24시 | 모레 0시 |
| 날짜 없이 24시에 | 기존 날짜 확인 규칙대로 |

## 학습 데이터에 주는 영향

사람은 같은 숫자를 여러 방식으로 말합니다. 18시를 "열여덟 시"라고도 하고 "십팔 시"라고도 합니다. STT가 한글로 적으면 사람이 말한 대로 들어오고, 숫자로 적으면 이 변환을 거쳐 "십팔 시"로 들어옵니다. 그래서 학습 문장에는 사람이 말하는 모양과 이 변환이 만드는 모양을 둘 다 넣습니다.

## 아직 확인하지 않은 것

- 보드 STT가 실제로 숫자를 숫자로 적는지, 한글로 적는지. 보드에서 "삼십 도 올려", "열한 시 반에 깨워 줘"를 말해 보고 확인합니다.
- STT가 "11시 반"처럼 반을 그대로 적는지, "11:30"으로 적는지.
