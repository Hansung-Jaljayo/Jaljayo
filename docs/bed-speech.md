# 침대가 하는 말

침대가 소리 내어 하는 말을 상황별로 모은 목록입니다. 모델은 정답 글자만 내고, 아래 문장은 보드 앱이 정해진 틀에 값을 넣어 말합니다.

기준은 상세설계서 9절 "대답 틀과 대답 예시" 표입니다. 이 문서는 그 표를 묶음별로 다시 나눈 것이니, 문장을 고칠 때는 설계서 표와 이 문서를 함께 고칩니다.

## 문장 규칙

- **무엇을 하는지 분명한 동사를 씁니다.** 바꿀까요, 저장할까요, 맞출까요, 삭제할까요, 끌까요처럼 씁니다. "할까요"처럼 무엇을 하는지 드러나지 않는 말은 쓰지 않습니다.
- **자세는 바꾸는 것입니다.** 직접 요청·동의 후에는 "TV 자세로 바꿀게요", 간접 표현에는 "TV 자세로 바꿀까요?"처럼 말합니다. "자세로 할까요"는 쓰지 않습니다. 각도를 정하는 말은 "30도로 맞출게요", "평평하게 맞출게요"처럼 맞춘다고 합니다.
- **알람을 지우는 말은 "삭제"로 통일합니다.** "취소"는 대상에 따라 예약 취소, 현재 요청 종료, 목표 이동 취소를 구분합니다.
- **앱은 "스마트폰 잘자요 앱"이라고 부릅니다.** "폰 앱", "앱"만으로 말하지 않습니다.
- **사용자 말은 이 규칙을 따르지 않아도 됩니다.** "잠 자세로 해줘"처럼 흐릿하게 말해도 알아들어야 하고, 학습 문장에도 그런 말을 넣습니다.
- `{ }`는 보드 앱이 채우는 값입니다. `{올릴게요·내릴게요}`처럼 가운뎃점으로 나눈 것은 상황에 맞는 하나를 고릅니다.

### 알람 대상 안내와 재질문 공통 규칙 (2026-10-17)

아래 대답 표의 `{대상 안내}`는 `{가리킨 말} {오전오후} {시각}`을 뜻합니다.

- **완료 안내는 어떤 알람인지와 결과를 함께 말합니다.** 기본 틀은 "{가리킨 말} {오전오후} {시각} 알람을 {결과}"입니다. 가리킨 말은 사용자가 지정한 날짜를 우선하고, 날짜를 말하지 않았으면 선택된 알람의 반복(매일·평일·주말·수요일 등)을 씁니다. 한 번 알람이면 울리는 날짜입니다. 오전·오후는 저장된 실제 시각을 확인해 항상 넣습니다. 모델이 생략한 오전·오후를 추측해 채우라는 뜻은 아닙니다. 시각 변경은 변경 전 대상 시각과 새 시각을 모두 오전·오후와 함께 말합니다.
- **시각·종류·난이도 변경, 다시 켜기, 끄기, 삭제, 기간 끄기, 한 번 건너뛰기에 같은 대상 안내를 적용합니다.** 날짜로 찾아 알람 자체를 끄는 경우에도 날짜는 대상을 가리키는 말이지 그날만 끈다는 뜻은 아닙니다. 날짜 지정 켜기는 그날 회차만 켰다고 결과에 밝힙니다. 기간 끄기는 대상과 끄는 시작·끝·재개일을 함께 안내합니다.
- **전체 대상은 하나씩 나열하지 않습니다.** "내일 알람 전체를 기본 알람으로 바꿨어요"처럼 날짜나 조건과 전체를 말합니다. 개별 시각을 나열하지 않는 이 경우는 오전·오후를 임의로 붙이지 않습니다. 이미 같은 종류면 "내일 오전 일곱 시 알람은 이미 기본 알람이에요"라고 합니다. 처음부터 후보가 없으면 날짜 지정 시 "내일은 알람이 없어요", 날짜가 없으면 "바꿀 알람이 없어요"라고 끝냅니다. 삭제·끄기·켜기도 동사에 맞춰 안내합니다. 단, 기존 '켜'의 없으면 생성 규칙과 '다시 켜'의 없으면 안내 규칙은 유지합니다.
- **침대가 요일 날짜를 읽을 때는 '이번' 대신 '다가오는'을 씁니다.** "다가오는 토요일 오전 아홉 시 알람을…"처럼 말하며, 다음 주로 지정된 날짜는 "다음 주 토요일"로 구분합니다. 사용자가 말하는 "이번 토요일"과 사용자 학습 문장은 바꾸지 않습니다.
- **여러 대상이 남으면 먼저 "어떤 알람을 바꿀까요?"라고 묻고 선택지는 모두 읽지 않습니다.** 한 번 답해도 여러 개면 한 번 더 좁혀 묻습니다. 시각이 다르면 "내일 오전 몇 시 알람을 바꿀까요?", 시각이 같으면 "어떤 요일 알람을 바꿀까요?"입니다. '내일·오전'은 실제로 확정된 조건일 때만 붙이고, 확정되지 않았으면 생략합니다.
- **대상 선택 중 없는 알람을 말하면 한 번 더 묻습니다.** "내일 오전 여덟 시 알람은 없어요. 어떤 알람을 바꿀까요?"처럼 알리고 재질문합니다. 최초 질문 뒤 추가 질문은 좁히기 또는 없는 대상 재질문을 통틀어 한 번입니다. 그 답으로도 정하지 못하면 "바꿀 알람을 찾지 못했어요. 설정은 바꾸지 않았어요"로 끝냅니다. 각 질문의 기존 10초 대기와 시간 초과 시 미변경 종료는 유지합니다. 삭제·끄기·켜기도 동사만 맞춰 같은 흐름을 씁니다.
- **요일로 반복 알람을 고르는 답은 저장된 반복 조건을 가리킵니다.** 수요일·목요일·평일 오전 일곱 시 알람이 있는데 선택 질문에 "금요일"이라고 답하면, 금요일 단독 알람이 없으므로 "금요일 오전 일곱 시 알람은 없어요"라고 합니다. 평일 알람이 금요일에 울린다는 이유로 대신 고르지 않습니다. 날짜로 그날 울릴 알람을 찾는 동작과 구분합니다. 시각과 요일까지 같은 중복 알람도 임의로 고르지 않고, 질문 한도 안에 식별하지 못하면 미변경 종료합니다.
- **"내일만 (그냥) 기본 알람"은 새 알람이 아니라 종류 변경입니다.** `change_type, date=tomorrow, type=basic, scope=once`로 받고 대상을 확정한 뒤 바꿉니다. 이 해석을 임의의 모든 생략 문장에 확대하지 않습니다.

### 알람 저장 겹침

말로 새 알람을 맞출 때 기존 일정에 완전히 포함되면 기존 알람이 있다는 안내로 끝내고 새로 만들지 않습니다. 일부만 겹치면 새 알람을 별도로 만듭니다. 앱에서는 완전히 같아도 그대로 저장하며 합치거나 덮어쓰지 않습니다. 기존 회차 삭제·요일 차감·겹친 날짜 제외·덮어쓰기 확인은 사용하지 않습니다. 실제로 울리는 날짜의 판단과 저장 응답 확인은 설계서를 따릅니다.

## 같은 시각 알람 실행 (2026-10-17 확정)

같은 시각에 실제 울릴 알람이 여러 개면 가장 최근에 설정·수정한 알람 하나만 울립니다. 나머지는 그 회차만 실행하지 않고, 화면 기록에 "같은 시각의 더 최근 알람이 실행되어 울리지 않았어요"를 남깁니다. 이 문구를 알람이 울리는 동안 말로 읽지는 않습니다. 기존 반복 설정은 유지하고, 선택된 알람이 끝난 뒤에 뒤늦게 울리지 않습니다.


### 알람 늦추기 실행 구분 (2026-10-17 결정)

- 명시적인 기존 알람 늦추기 출력은 `change_time, time_type=later`로 통일합니다. 별도 `snooze` 명령은 없으며 말한 시간을 그대로 HH:MM으로 냅니다. 십분은 00:10, 두 시간은 02:00입니다. 시간 생략은 none, 범위 생략은 scope=none입니다. 모델은 알람 진행 상태를 추측하지 않습니다.
- 알람 시작 전에는 종류와 관계없이 원래 예정 시각을 변경합니다. 기존 대상·날짜·범위 규칙을 적용하고 30분 제한을 적용하지 않습니다.
- 질문 알람의 문제 답변 중이나 침대 이탈 알람의 이탈 대기 중, 버튼으로 소리를 멈춘 상태에서는 보드가 지금부터 이번 회차만 미룹니다. 최대 30분, 시간 생략은 5분입니다. 반복 설정은 바꾸지 않습니다.
- 30분 초과 시 임의로 줄이거나 시각 설정을 바꾸지 않고 "최대 삼십 분까지 미룰 수 있어요. 몇 분 미룰까요?"라고 묻습니다. 기존 10초 응답 대기를 적용하고 응답이 없으면 미루지 않습니다.
- 침대 이탈 알람도 버튼으로 소리를 멈춘 뒤 최대 30분 미룰 수 있습니다. 미루기 성립 시 1분 이탈 대기는 중단하고, 미룬 시간이 끝나면 같은 침대 이탈 알람으로 다시 울립니다. 미루지 않으면 기존 1분 이탈 대기를 유지합니다. 일반 알람은 버튼으로 해당 회차가 종료되므로 이 경로에 들어오지 않습니다.

### 더 자겠다는 말과 기존 알람 변경 구분 (2026-10-17 추가 확정)

- 아무 맥락 없이 "오분만 더 잘게"라고 하면 기존 알람과 다음 알람을 전혀 바꾸지 않습니다. "5분 뒤에 깨워드릴까요?"라고 새 알람을 제안합니다. 동의하면 지금부터 5분 뒤 새 알람을 만들고, 거절·10초 무응답이면 아무것도 변경하지 않습니다.
- 모델 정답은 `set, time=00:05, time_type=relative, confirm=yes`입니다. 잠을 더 자려는 말에 기존 알람 변경 의도가 명시되지 않으면 change_time으로 추측하지 않습니다. 시간 생략은 none이며 일반 상태에서는 시간을 묻고 확인합니다.
- 질문 알람 답변 중 또는 침대 이탈 알람의 소리를 버튼으로 멈춘 뒤 이탈 대기 중에는 보드가 이 더 자기 요청을 현재 회차 미루기로 처리합니다. 지금부터 계산하고 최대 30분, 시간 생략 시 5분입니다. 새 알람이나 반복 설정을 만들거나 고치지 않습니다. 30분 초과 시 기존 안내대로 다시 묻습니다.
- 명시적인 "알람 오분 미뤄"는 기존대로 change_time/later입니다. 모든 relative set을 미루기로 바꾸는 규칙이 아닙니다. 모델 출력만으로 상태를 추측하지 않습니다.

### 다시 깨우기·짧은 기간 요청 (2026-10-17 추가 결정)

- "십분 있다 다시 깨워", "오분 뒤에 다시 울려줘", "삼분만 더", "육분만", "한 오분만"도 더 자기 제안과 같습니다. `set, time_type=relative, confirm=yes`로 말한 시간을 보존합니다. 시간 자체가 없으면 time·time_type은 none입니다.
- 일반 상태에서는 "N분 뒤에 깨워드릴까요?"라고 묻고 동의한 뒤 새 알람을 만듭니다. 기존 알람이나 다음 알람을 자동 변경하지 않습니다. 질문 알람 답변 중과 침대 이탈 알람의 버튼 정지 후 이탈 대기 중에는 현재 회차 미루기 규칙(최대 30분)을 적용합니다.
- "오분 미뤄바"처럼 변경을 요청하면 알람이라는 낱말이 없어도 `change_time, time_type=later`입니다. "다시 울리도록 미뤄"도 명시적인 변경입니다. 다만 "이십분만 더 자게 미뤄"처럼 더 자겠다는 의도를 말하고 알람 대상을 지정하지 않은 문장은 앞서 정한 더 자기 제안을 유지합니다. '미뤄' 한 단어만으로 이를 기존 알람 변경으로 바꾸지 않습니다.


## 2026-10-19 사용자 결정 — 문맥과 범위 처리

이 절은 합의된 제품 동작입니다. 현행 모델 출력 규격과 보드 구현은 아직 전부 반영되지 않았습니다. 아래와 충돌하는 이전 일반 규칙에는 이 절을 우선 적용합니다. 평가 원문을 학습 예시로 전환하는 기록이 아닙니다.

- **의도와 상태를 구분합니다.** 모델은 발화의 뜻과 값만 전달하고, 보드는 대기 질문·확정된 대상·진행 중 알람 상태로 실행을 결정합니다. 맥락이 없는 지시대명사에서 다음 알람을 임의 선택하지 않습니다. 사용자에게 대상과 부족한 값만 순서대로 묻고, 이미 확정된 값은 다시 묻지 않습니다.
- **정지 전용 말은 움직임만 멈춥니다.** 정지 의미의 짧은 발화를 이동 중 받으면 즉시 정지하고, 이미 정지 중이면 그대로 유지합니다. 이 경로를 미래 예약 취소 확인으로 돌리지 않습니다. 명시적인 예약 취소와 진행 중 요청 취소는 별도입니다. 새 정답은 halt mode=motion으로 통일하며 contextual은 같은 동작의 옛 출력 호환용입니다. 실제 보드 분기는 별도 구현·검증해야 합니다.
- **부위와 작은 양만 있는 조절 요청은 기본으로 5도 올립니다.** 같은 부위를 내리던 유효한 맥락이면 5도 더 내립니다. 숫자·명시 방향이 있으면 그것을 우선합니다. 단순 부위 이름 대답은 이 예외가 아니며, 앞서 정한 조절 맥락 유효 시간(이동 중·종료 후 10초)을 사용합니다.
- **저장 의도와 사용 의사를 구분합니다.** 현재 각도를 특정 목적에 저장하라는 뜻이 확인되면 목적별 저장값만 갱신합니다. 이미 같은 값이면 유지합니다. 단순 사용 의사나 신체적 효과의 기대를 저장·이동 명령으로 추측하지 않습니다. 과거 시점만 가리키고 행동을 말하지 않는 발화도 되돌리기로 단정하지 않습니다.
- **범위 보존:** 특정 주의 토·일 회차만 끄는 것과 매주 주말 알람 자체를 끄는 것은 다릅니다. 전자는 해당 두 날짜 회차만 건너뛰고 이후 반복은 유지합니다. 후자는 다시 켤 때까지 꺼 둡니다. 켜진 상태만 삭제하라는 요청은 꺼진 알람을 보존합니다. 조건에 맞는 대상이 없으면 없다고 안내합니다. 삭제 확인 규칙은 유지합니다.
- **삭제 날짜와 기간 시작:** 날짜를 지정한 삭제는 그날 울릴 알람을 찾아 그 알람 자체를 삭제하는 요청입니다. 후보가 여러 개면 대상을 확인합니다. 기간 끄기의 시작을 명령에서 지정하지 않았으면 지금부터 끄며, 배경 사유 속 날짜를 시작일로 옮겨 붙이지 않습니다. 종료 계산은 기존 기간 규칙을 유지합니다.
- **간접 휴식 의사:** 다음 날 오전 알람을 쉬겠다는 합의된 간접 의도는 다음 날 오전 회차 전체를 건너뛸지 확인하고, 동의 전 변경하지 않습니다. 이 해석을 모든 일반 대화로 확대하지 않습니다.
- **요일 알람 켜기:** 요일은 말했으나 시각이 없는 요청은 시각부터 묻습니다. 오전·오후도 필요하면 확인합니다. 확정된 시각·반복 여부·요일 조건이 같은 알람을 찾고, 하나가 꺼져 있으면 켜고 이미 켜져 있으면 안내합니다. 같은 조건이 여러 개면 대상 선택 규칙을 적용합니다. 특정 주에만 울리는 알람은 매주 반복 알람의 재사용 대상이 아닙니다. 그런 알람만 있으면 그대로 보존하고 매주 반복 알람을 새로 만듭니다. 기존 알람의 반복 요일을 임의 확장하지 않습니다.
- **종류만으로 새 알람 설정 의도를 받기로 한 경우:** 필요한 시각을 묻고, 답하기 전에는 만들지 않습니다. 생략 발화 모두를 임의로 새 설정으로 일반화하지 않습니다.
- **대답의 정보:** 기간, 지금부터의 상대 시점, 대상 전체, 덧셈 난이도, 날짜와 시각으로 지정한 대상은 기다리던 질문에 채웁니다. 기간을 시계 시각으로 바꾸거나 전체 대상을 반복 범위로 바꾸지 않습니다. 새 명령으로 임의 실행하지 않습니다.
- **망설임:** 의미 있는 응답을 아직 준비하는 말소리는 기존 응답 대기 마감까지 기다립니다. 동의·명령으로 처리하거나 마감을 새로 늘리지 않습니다. 망설임만으로 시간 내 응답 성공 처리도 하지 않습니다. 마감 뒤에는 원래 요청의 무응답 규칙을 따릅니다. 의도를 전달하지 못한 완결 요청의 재질문과 구분합니다.
- **현재 회차 미루기:** 질문 알람 답변 대기와 침대 이탈 알람의 버튼 정지 후 이탈 대기에서 최대 30분 허용합니다. 명시 시간이 없으면 기존 5분 기본값을 유지하며 초과 값은 자르지 않고 다시 묻습니다. 이탈 알람은 미루기 성립 때 1분 대기를 중단하고 같은 종류로 다시 울립니다. 반복 설정과 다른 알람은 변경하지 않습니다. 현재 회차만 지칭하는 요청은 그 회차가 없을 때 처리 불가이며, 다음 알람 변경이나 새 알람 생성으로 대신하지 않습니다. 일반 상태의 명시적 새 상대 알람은 새로 설정할 수 있고, 더 자기 제안은 기존 동의 절차를 유지합니다.

## 2026-10-19 최신 결정: 간접 자세 요청은 동의 후 실행

이 절은 기존의 활동·졸림·불평 표현을 즉시 실행으로 적은 문장보다 우선합니다. 실제 보드 구현 완료를 뜻하지 않습니다.

- 자세를 바꾸거나 각도를 올리고 내리라는 명확한 요청은 confirm=no입니다. 짧아도 동작이 분명한 “머리 위로”, “평평하게”, 숫자로 지정한 각도, 명시적인 자세·모드는 직접 요청입니다. 필수 값이 없으면 먼저 물으며, confirm=no가 미확정 값의 추측을 허용하지 않습니다.
- 활동·희망·상태·불평에서 동작을 추론한 경우는 confirm=yes입니다. “쉴래”, 독서·TV를 하겠다는 말, 졸리다는 말, 높다는 불평은 이동 전 동의를 묻습니다. 활동 낱말만 말한 경우도 이동 명령으로 단정하지 않습니다. 불분명한 뜻을 억지로 자세 제안으로 만들지는 않습니다.
- 원하는 자세·각도를 추출하는 기존 기준은 유지합니다. 휴식은 휴식 자세, 잔다는 의사는 양쪽 평평하게, 높다는 불평은 해당 부위 조금 내리기입니다. 바뀌는 것은 실행 전에 동의를 받는 과정입니다. 배경 의사와 함께 명시적인 조절을 요청하면 그 직접 요청을 따릅니다.
- call/adjust/undo/reserve/change_reserve에 confirm=yes/no를 필수로 추가합니다. set_default/cancel_reserve는 기존 confirm을 같은 기준으로 재검토합니다. halt는 확인 없이 즉시 정지합니다.
- 부위·각도·시각 등 빠진 값을 먼저 채운 뒤, confirm=yes이면 구체적인 최종 동작을 말하고 동의를 받습니다. 부위 질문에 답했다는 사실은 실행 동의가 아닙니다. 직접 실행 요청으로 명확히 다시 말하면 그 새 요청을 처리합니다.
- 동의 전에는 모터 이동뿐 아니라 현재 목적, 기본 자세 저장, 예약 추가·변경·취소, 되돌리기 기록도 변경하지 않습니다. 거절·요청 취소·10초 응답 만료는 미변경 종료입니다. 질문 안내가 끝난 뒤 기존 10초 대기 규칙을 적용합니다. 다른 요청으로 대체되면 이전 제안은 폐기합니다.
- 동의는 해당 제안의 부위·방향·목표·시각에만 유효합니다. 제안 후 상태가 달라져 실제 동작이 달라지면 다시 확인합니다. 확인된 요청의 중복 실행을 막습니다.
- 미래 활동 의사는 예약 생성 전에 확인합니다. 사용자가 동의해서 생성한 예약은 정한 시각에 실행하며, 실행 때 같은 동의를 다시 요구하지 않습니다.
- 명시적 정지·취소·거절을 동의 대기로 늦추지 않습니다. 정지와 안전 제한은 동의 처리보다 우선합니다.

| 입력 성격 | 안내 및 처리 |
|---|---|
| 쉬겠다는 의사 | “휴식 자세로 바꿀까요?” → 동의 후 이동 |
| 졸리다는 상태 | “침대를 평평하게 할까요?” → 동의 후 이동 |
| 다리가 높다는 불평 | 양 말이 없으면 “다리를 10도 내릴까요?”, “다리가 좀 높아”처럼 양 말이 있으면 5도(11/10) → 동의 후 이동 |
| 부위 없는 높다는 불평 | 부위 질문 → 답변 → 구체적 내림 동의 질문 → 동의 후 이동 |
| 미래에 자겠다는 의사 | 시각 등 확인 → “그 시각에 평평하게 바꾸도록 예약할까요?” → 동의 후 예약 |
| 명시적인 머리 올리기 | 필요한 값 확인 후 이동 안내·실행 |
| 명시적인 멈춤 | 동의 질문 없이 즉시 정지 |

언어 모델은 confirm을 출력하고, 보드는 실제 질문·대기·동의·상태 재검증을 담당합니다. 글만 수정했다고 보드에 적용된 것으로 보고하지 않습니다.


## 2026-10-19 맥락 참조 선택·유지 처리

최신 revision: `context-reference-2026-10-19`. 사용자 결정은 상황에 따라 연결하고, 상황이 없으면 의도를 묻는 것입니다. 보드 구현은 별도입니다.
